## 기록자 작성법 (Google Docs)

한 줄에 발언 하나. 줄 앞에 태그를 붙이면 화면에서 색으로 구분되고, AI 정리 정확도도 올라갑니다.

```
[경험] 도산: 저녁마다 제방길을 걷는데 가로등이 드문드문해요
[불편] 비 오면 산책로가 진흙탕이 돼요
[자원] 걷기 동아리가 매주 화요일에 모여요
[아이디어] 두 동이 같이 줍깅 데이를 정하면 어떨까요
[실천] 매월 셋째 토요일 두 동 합동 하천 줍깅하기
[협력] 제방길 가로등·CCTV 추가 설치 요청
```

- 태그를 생략하면 바로 위 태그를 이어 씁니다. `■ 이용 경험` 같은 소제목 줄로 바꿔도 됩니다.
- `도산:` 처럼 동 이름을 앞에 쓰면 카드에 동이 표시됩니다.
- `※`로 시작하는 줄은 화면에 나가지 않습니다(메모용).
- 이미 쓴 줄을 고치면 새 발언으로 한 번 더 올라갑니다. 오타는 그대로 두는 편이 낫습니다.

## 설치 (LIVE 모드)

1. Google Drive에서 새 스프레드시트 「광산자치아고라 관제」를 만들고 **확장 프로그램 → Apps Script**를 엽니다.
2. `apps-script/Code.gs` 내용을 붙여 넣고, 프로젝트 설정에서 "appsscript.json 표시"를 켠 뒤 `apps-script/appsscript.json`으로 바꿉니다.
3. 편집기에서 `setup` 함수를 실행 → 권한 허용. `tables` 시트와 12개 기록 Docs(양식 포함)가 생깁니다.
   - 테이블 구성(분야·동·대상공간)은 공론 의제 분류(참고3)로 만든 **초안**입니다. `tables` 시트에서 실제 배치대로 고쳐 주세요.
   - 각 Docs 링크를 해당 테이블 기록자에게 **편집 가능**으로 공유합니다.
4. 프로젝트 설정 → 스크립트 속성
   - `ADMIN_KEY` : 관제 비밀번호 (setup이 `agora2026`으로 만들어 둠 — 꼭 바꾸세요)
   - `GEMINI_API_KEY` : Google AI Studio에서 발급
   - `GEMINI_MODEL` : 선택. 기본 `gemini-3.8-flash`
   - `GEMINI_FALLBACK` : 선택. 첫 모델이 붐빌 때(503) 차례로 쓸 모델. 기본 `gemini-3.5-flash,gemini-flash-latest`
   - 편집기에서 `testGemini`(키·모델 확인), `testSummarize`(지금 기록으로 요약 시험)를 실행할 수 있습니다.
5. **배포 → 새 배포 → 웹 앱** (실행: 나, 액세스: 모든 사용자) → URL 복사.
6. `config.js`의 `window.AGORA_API`에 URL을 넣고 이 폴더를 웹에 올립니다(GitHub Pages 등). 참가자 휴대폰이 `vote.html`에 접속해야 하므로 공개 주소가 필요합니다.
7. 관제 패널 → 연결 설정에서 관제 비밀번호를 입력합니다.

행사 직전에는 Apps Script에서 `resetForEvent`를 실행하면 리허설 기록·요약·투표가 지워지고 Docs는 양식만 남습니다.

## 시뮬레이션 (DEMO 모드)

`config.js`가 비어 있거나 주소 뒤에 `?demo`를 붙이면 같은 브라우저 안에서만 동작하는 시뮬레이션이 됩니다.

```bash
python3 -m http.server 8794
```

1. `http://localhost:8794/control.html` 열기 → **대형 스크린 열기**
2. 시뮬레이션 → 자동 기록 시뮬레이션 켜기 → 진행 단계 「의제공론화」
3. 세부 단계를 넘기며 피드 확인 → 「결과 정리」에서 AI 요약 실행(데모는 태그 기반 정리)
4. 결과 공유 → 후보 만들기 → 투표 열기(가상 참가자가 투표) → 투표 결과 → 3·2·1 구호

## 알아 둘 점

- **지연 시간**: Docs는 푸시 알림이 없어 스크린이 5초마다 가져옵니다(서버 4초 캐시). 기록 후 화면 표시까지 보통 5~10초 걸립니다. PRD의 '1초 이내'는 Docs 방식으로는 어렵습니다.
- **발언 시각**은 스크린이 그 줄을 처음 본 시각입니다(Docs에는 줄 단위 시각이 없음).
- **AI 요약은 검수 후 송출**: Gemini 결과는 `summary` 시트와 관제 패널에 들어오며, 관제반이 고쳐 저장한 내용이 결과 화면에 나갑니다. Gemini가 실패하면 `[실천]`/`[협력]` 태그 줄로 대신 정리할 수 있습니다.
- **투표**는 기기당 1표(다시 투표하면 덮어씀)이며 로그인은 없습니다. 150명이 동시에 접속해도 되도록 투표 페이지는 8~12초 간격으로만 서버를 확인합니다.
- **Wi‑Fi 장애**: 관제 패널의 수동 발언 푸시로 화면에 직접 띄울 수 있습니다. 스크린 PC가 오프라인이 되면 마지막 화면이 유지됩니다.
- 분야는 PRD의 3개(하천·공원·길)에 변경계획 참고3의 **공동공간 활용활동**을 더해 4개(보라색)로 구성했습니다.
